# Capability migration contract

Reaserch is evidence and legacy authority, not a migration checklist.

For each candidate capability:

1. Name the user/system outcome it provides.
2. Demonstrate that the outcome is needed in Take-2.
3. Reconstruct the capability independently from the legacy representation.
4. Compare the clean-sheet version with the legacy behavior.
5. Run PD, rival, regression, and strict-gain review.
6. Choose exactly one current disposition:
   REIMPLEMENT, IMPORT, REFERENCE, DISCARD, or OPEN.
7. Migrate the smallest behaviorally sufficient unit.
8. Run the vertical-slice fitness checks.
9. Keep legacy authority until Take-2 has prospectively demonstrated replacement.

File count, age, apparent importance, and historical effort are not migration grounds.
