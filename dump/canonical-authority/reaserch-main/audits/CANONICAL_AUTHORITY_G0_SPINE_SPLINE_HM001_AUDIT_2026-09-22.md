## 2. Three structures must remain distinct

The current project contains three different structures that had been partly discussed
under the general idea of a spine.

### 2.1 Stable argument spine

SPINE.yaml owns the stable paper identity:

A -> Q -> H[F] -> R -> B -> C

with:

- A = fixed Rashi-Ramban proposition-level collision;
- Q = third-party truth-directed adjudication question;
- H[F] = admitted source-grounded response space;
- R = source-to-target application;
- B = adjudicative success requirement;
- C = bounded result and contribution.

This is the real argument spine.

### 2.2 Reader-facing spline

The current method and manuscript contract refine the middle of the argument spine into
a smoother reader-facing dependency path:

A
-> Q
-> PROFILE(H[F])
-> TRACE
-> DISCRIMINATE
-> RECOGNIZE
-> [COMPOSE when several completed grounds materially conflict]
-> C

This audit uses the user's term "spline" for that reader-facing refinement.

The spline is not a second theory and does not replace the real spine.

### 2.3 Complete CANON:G0 dependency graph

CANON:G0 asks for more than a valid argument. It asks for a rigorous source-grounded
peer-reviewed paper.

Therefore the complete G0 dependency graph also includes side branches for:

- source and edition verification;
- provenance closure;
- corpus-admission and scope control;
- nearest-neighbor and novelty closure;
- manuscript execution;
- journal-specific framing;
- submission, review, revision, and the external publication outcome.

The stable argument spine intentionally does not own these jobs.

Therefore:

stable argument spine != reader spline != complete G0 dependency graph.

## 3. HM-001 destructive test of the real spine

### A: fixed collision

Remove A and the project loses the controlled truth target and the proposition pair
that makes later source-to-target testing inspectable.

Verdict: LOAD_BEARING.

### Q: third-party adjudication question

Remove Q and the paper can still describe Jewish authority structures but no longer has
a fixed criterion for asking what they contribute to deciding between incompatible
truth-apt claims.

Verdict: LOAD_BEARING.

### H[F]: admitted response space

Remove H[F] and there is no controlled set of source-grounded Jewish structures to
reconstruct or compare.

Verdict: LOAD_BEARING.

Qualification: the inventory is purposive and non-exhaustive. This is compatible with
the bounded case result, but the exact admission rationale remains result-sensitive for
claims about methodological breadth, disciplinary reach, and novelty.

### R: source-to-target application

Remove R and native authority functions can be treated as though they automatically
transfer to the Genesis truth target.

That destroys the central source/application distinction.

Verdict: LOAD_BEARING.

### B: adjudicative success requirement

Remove B and truth relevance, legitimacy, authority, provenance, authentication, or
case proximity can be mistaken for a usable discriminator.

Verdict: LOAD_BEARING.

### C: bounded result and contribution

Remove C and the project has analysis without a controlled conclusion, scope boundary,
or contribution.

Verdict: LOAD_BEARING.

## 4. HM-001 edge test of the real spine

### A -> Q

The fixed contradiction earns a third-party truth-directed question.

The move is not from "there is disagreement" to "someone must decide." It is from an
explicit pair of incompatible truth-apt claims to the question of what, if anything,
can provide later epistemic grounds concerning that pair.

Verdict: LOAD_BEARING.

### Q -> H[F]

The question motivates inspection of Jewish epistemic, interpretive, institutional,
transmission, authority, and privileged-access structures.

The edge survives, but its admission basis is only partly explicit. "Purposive,
materially different, non-exhaustive" controls scope but does not by itself fully state
why these source families, and not another equally plausible set, constitute the
current comparison sample.

Verdict: CONDITIONALLY_LOAD_BEARING with an OPEN admission-rationale coordinate.

### H[F] -> R

Native source functions must be reconstructed before application, and application must
not silently rewrite those native functions.

Verdict: LOAD_BEARING.

### R -> B

A source-to-target relation must be tested for rival-specific discrimination and
evaluator-usable warrant.

Verdict: LOAD_BEARING.

### B -> C

Completed route-level grounds can support a case-level conclusion, but this edge is not
always one simple arrow.

When several completed grounds conflict, an independently licensed COMPOSE or defeat
relation is required.

When no current source package completes TRACE, the current bounded negative result is
reached without activating downstream RECOGNIZE or COMPOSE in the fixed case.

Verdict: LOAD_BEARING but CONDITIONALLY REFINED.

## 5. Rival-spine tests

The following rival reconstructions were tested analytically.

### Collapse H[F] and R

This erases the distinction between what a source structure does natively and what the
paper adds when applying it to the fixed case.

Rejected.

### Collapse R and B

This erases the distinction between tracing a source-attributable relation to the
target and establishing that the relation actually discriminates the rivals and is
epistemically usable.

Rejected.

### Replace B with generic truth relevance

This admits routes that are truth-related but not proposition-specific, asymmetric, or
evaluator-usable.

Rejected.

### Promote PROFILE to a new independent success stage in the real spine

PROFILE is mandatory typed setup, but a well-formed TRACE already presupposes the
profiled source and native output.

Adding PROFILE as a new independent success conjunct would overcount the method.

Rejected as a real-spine replacement; retained in the reader spline.

### Promote COMPOSE to an unconditional real-spine node

COMPOSE is required only when several completed grounds materially conflict.

The current fixed case has no completed TRACE ground to compose.

Rejected as an unconditional spine node; retained as a conditional B-to-C refinement.

Result: the macro real spine survives these rival reconstructions as a strong minimal
argument-identity representation.

## 6. Formal alignment of real spine and spline

Define a refinement map from the reader spline to the real spine.

- A maps to A.
- Q maps to Q.
- PROFILE maps primarily to H[F].
- TRACE maps to R.
- DISCRIMINATE maps to the source-side part of B.
- RECOGNIZE maps to the evaluator-uptake part of B.
- COMPOSE refines the conditional transition from completed B-level grounds to C.
- the bounded result and contribution map to C.

The spline therefore expands load-bearing internal jobs without changing the paper's
stable identity.

## 7. General method spline versus realized case spline

The general method path is:

A
-> Q
-> PROFILE
-> TRACE
-> DISCRIMINATE
-> RECOGNIZE
-> [COMPOSE if needed]
-> C

But the current Rashi-Ramban evidence does not traverse that entire path.

The realized case path is:

A
-> Q
-> PROFILE
-> TRACE obstruction
-> bounded C_case

because no currently admitted source package completes TRACE to I_S.

DISCRIMINATE, RECOGNIZE, and COMPOSE are therefore genuine method jobs but dormant
downstream jobs in the current case.

This distinction is essential for manuscript accuracy. The article must not narrate
the fixed case as though it successfully passed gates that are only characterized in
the general framework or supported by positive controls and holdouts.

## 8. C is a stable macro node but not an atomic job

The current integrated architecture already distinguishes:

- C_case: bounded fixed-case result;
- C_method: general comparative method;
- C_disciplinary: broader authority and religious-studies implication;
- C_publication: derivative publication positioning.

HM-001 confirms that these have different support.

The real spine can keep C as a stable macro identity node.

The complete G0 dependency graph must expand C because publication readiness does not
follow from C_case alone.

A current dependency sketch is:

C_case + route characterization + validation
-> C_method

C_case + C_method + relevant field literature
-> C_disciplinary

C_case + C_method + C_disciplinary + source closure + novelty closure + manuscript execution
-> C_publication-ready

C_publication-ready + submission/review/revision
-> peer-reviewed publication outcome

The last transition is partly external to the research system.

## 9. H[F] admission is the main residual argument-spine coordinate

The current bounded case result is explicitly conditional on the admitted reconstructed
corpus, so non-exhaustiveness does not invalidate the result.

However, the broader claims gain force from the fact that the selected modules are
materially heterogeneous and relevant.

The current repository states that the corpus is purposive and non-exhaustive but does
not yet provide one compact explicit admission basis answering:

- why these response families are in the paper;
- what makes a new family materially different rather than redundant;
- what would justify excluding a plausible family;
- how module admission affects the strength of C_method, C_disciplinary, and novelty.

This is not a hidden universal-exhaustiveness requirement.

It is a bounded-selection and representativeness-for-purpose requirement.

Status: OPEN / CONDITIONALLY RESULT-SENSITIVE.

## 13. Audit verdict

The canonical argument spine survives HM-001 and rival reconstruction.

It does not need replacement.

The reader-facing spline is a valid refinement, but it needs its own durable control
object so it is not repeatedly reconstructed from MANUSCRIPT_CONTRACT.md and
RESEARCH_ARCHITECTURE.yaml.

The complete CANON:G0 dependency graph is broader than both because the goal includes
source closure, novelty, manuscript production, and peer-reviewed publication.

The highest-value repair is therefore representational rather than theoretical:

- preserve SPINE.yaml unchanged as stable argument identity;
- materialize the reader spline explicitly;
- record the spline-to-spine refinement relation;
- update the CANON:G0 goal-spine registry state;
- keep current broad theory freeze intact;
- route remaining work toward corpus/source closure, novelty closure, and manuscript
  execution.
