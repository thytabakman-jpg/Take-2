The project has multiple distinct architectures that must not be flattened:

1. goal/control architecture;
2. substantive argument/research architecture;
3. source/evidence/provenance architecture;
4. reader/manuscript architecture;
5. project-operational/workstream architecture;
6. human-facing cockpit/orientation architecture.

The existing project page already correctly acts as an interface over these structures.

## Recursive findings

### A — Semantic architecture is stronger than physical taxonomy

The load-bearing dependency graph is already largely explicit in:
GOALS -> GOAL_SPINES / SPINE -> RESEARCH_ARCHITECTURE -> SOURCE_MODULES / SOURCE_REGISTRY /
PROVENANCE -> STATE -> MANUSCRIPT_CONTRACT / PROJECT_PAGE.

Physical adjacency is not what creates these dependencies.

### B — Several files have representational overlap without authority duplication

PROJECT_PAGE, PROJECT_PAGE_APPENDIX, MANUSCRIPT_CONTRACT, RESEARCH_ARCHITECTURE, and
GOAL_SPINES describe overlapping aspects of the project but have distinct authority roles.

The current architecture explicitly distinguishes them.

Therefore apparent redundancy is not by itself a folder defect.

### C — The strongest organizational boundary is function, not chronology

Audits, source evidence, discovery, current state, manuscript control, and orientation have
different lifecycle semantics.

Chronological grouping would misrepresent authority.

### D — The principal remaining ambiguity is human navigation / taxonomy

The project can be understood semantically, but the repository tree still requires the user
to know which files are control, research, evidence, history, manuscript, and orientation.

This is a human-facing problem more than a research-authority problem.

### E — Active work is the second organizational boundary

The current project has several open coordinates but they do not all have the same lifecycle.
Active work, dormant OPEN research coordinates, publication branches, and historical audits
must remain distinct.

### F — Historical material must remain recoverable but must not govern current authority

The existing audit corpus contains substantial discovery history. Moving it wholesale into
current architecture would recreate the chronology/dependency confusion the project has
already repaired.

### G — Existing reusable systems are upstream infrastructure

Goal-Spine, HM-001, relational PD, ImprovementCore, RepairEscalation, provenance,
traceability, derived-state, and workstream machinery are better treated as shared systems
than cloned into Canonical Authority.

### H — Folder taxonomy does not yet have a demonstrated catastrophic defect

The audit does NOT establish that a wholesale folder reorganization is necessary.

The strongest surviving defect class is:
HUMAN_ORIENTATION / FUNCTIONAL_TAXONOMY AMBIGUITY.

## Destructive conceptual tests

Removing the project page:
- substantive architecture survives;
- human orientation degrades materially.

Removing GOALS:
- project-goal authority fails.

Removing SPINE:
- substantive identity becomes harder to recover.

Removing SOURCE_REGISTRY:
- evidence identity/provenance fails.

Removing MANUSCRIPT_CONTRACT:
- publication realization becomes under-specified but research architecture can survive.

Removing the audit corpus:
- current authority can survive if current source/control objects remain;
- historical recoverability degrades.

This confirms the distinction between semantic load-bearingness and operational usefulness.

## Rival organizational models

At least three remain viable:

T1 current hybrid;
T2 stronger typed folder separation;
T3 root authority + typed non-authoritative subtrees.

No model yet demonstrates sufficient strict gain to justify physical mutation.

## Recursive stopping condition

Further descent into individual research claims does not materially improve the organizational
decision unless a candidate taxonomy would move them or change their authority interpretation.

Therefore the organizational HM-001 audit stops at this level.

## Final HM-001 result

The whole-project organizational problem is localized to:

1. human-facing taxonomy/navigation;
2. active-work visibility;
3. explicit reuse of shared systems.

No evidence currently justifies rebuilding the substantive research architecture or creating
a new local copy of the existing PD/control systems.

Feed this result into ImprovementCore before any taxonomy decision or physical change.
