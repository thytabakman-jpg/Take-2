# Canonical Authority Organizational Repair — Five-Tool Plan Audit

Date: 2026-09-23

## Five tools selected from prior successful work

### 1. ImprovementCore
Why it earned inclusion:
It repeatedly compressed large discovery sets into a small number of actionable architectural
changes and prevented unnecessary promotion.

Current use:
Plan selection, phase gates, strict-gain testing, non-regression, termination/replanning.

### 2. Goal-Spine Audit
Why it earned inclusion:
The Canonical Authority work repeatedly exposed goal/type/spine ambiguity and improved the
project by distinguishing goal, substantive target, constraints, invariants, frontier, and
next action.

Current use:
Protect canonical goals and spine while aligning the organizational layer.

### 3. Multi-Level / Relational PD
Why it earned inclusion:
The 2026-09-23 multi-object and cross-level campaigns produced the strongest structural
discoveries: typed relations, non-flat functions, gate DAGs, target-edge localization,
representation versus identity, and cross-level dependencies.

Current use:
Compare alternative taxonomies, detect shared generators, and prevent local folder logic
from being mistaken for semantic structure.

### 4. RepairCore / RepairEscalation
Why it earned inclusion:
The ownership project showed why repeated local fixes need escalation. The repair policy gives
explicit cycle detection and one-level-up escalation.

Current use:
Detect taxonomy/page/schema oscillation and prevent repeated folder moves.

### 5. Recursive Dependency / Coverage Audit (HM-001)
Why it earned inclusion:
The goal-spine protocol requires recursive reconstruction of load-bearing dependencies,
destructive tests, rival-spine testing, referent continuity, and audit-coverage analysis.

Current use:
Determine whether a folder/object is actually load-bearing, merely historical, or
representational before moving it.

## Tool combination result

The five tools have distinct jobs:

ImprovementCore = what is worth doing?
Goal-Spine = what must remain load-bearing?
Relational PD = how do the pieces relate?
RepairCore = where is the real repair frontier?
HM-001 = what does the structure actually depend on?

No tool subsumes the others.

## Plan-level consequences

1. The current project cockpit is already repaired and is not rebuilt.
2. Goal/spine semantics are protected before folder design.
3. Physical taxonomy is treated as a hypothesis to test, not an assumed problem.
4. Every candidate folder move requires a dependency explanation.
5. Repeated layout failure escalates to the taxonomy model.
6. A phase can terminate early when the current organization passes its tests.
7. Organizational improvements must not alter the substantive research architecture merely
   because the latter is easier to display one way.
