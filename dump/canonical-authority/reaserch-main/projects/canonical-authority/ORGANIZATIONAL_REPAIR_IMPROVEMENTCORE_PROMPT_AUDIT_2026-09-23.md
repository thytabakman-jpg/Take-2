# ImprovementCore Prompt Audit — Canonical Authority Organizational Repair

Date: 2026-09-23

## Target prompt

Design the complete staged repair plan for Canonical Authority's organizational structure,
using the repository's existing architecture and prior conversational work, with adaptive
ImprovementCore gates and the existing Goal-Spine, Relational PD, SemanticPreflight,
ExactObjectPreflight, PortfolioHealth, Workstream/Concurrency, MigrationContract,
Traceability, DerivedStateLiveness, and RepairEscalation controls.

## ImprovementCore assessment

### Correct interpretation

The task is not to redesign the Canonical Authority research argument.

The task is to make the existing research architecture operationally legible and internally
coherent:
- one authoritative home for each class of information;
- explicit distinction between source, derived, control, history, and manuscript-facing material;
- stable project entry/navigation;
- goal/spine/state alignment;
- clear relationship among research object, artifacts, source modules, control maps, and manuscript contract;
- no duplicate authority.

### Protected current structures

- canonical G0-G2 goals;
- SPINE.yaml;
- SPLINE.yaml;
- RESEARCH_ARCHITECTURE.yaml v1.2.0;
- STATE.yaml;
- CONTROL_MAP.yaml;
- GOAL_SPINES.yaml;
- SOURCE_REGISTRY.yaml;
- SOURCE_MODULES.yaml;
- DISCOVERY_MAP.yaml;
- CEILING_RAISE_REGISTER.yaml;
- PROVENANCE.yaml;
- ARTIFACTS.yaml;
- MANUSCRIPT_CONTRACT.md.

### Strict-gain requirement

Every organizational change must answer:
What ambiguity, duplication, routing cost, stale-state risk, or human orientation cost does
this remove?

Folder changes without a demonstrated structural gain do not proceed.

### Core danger

The project has enough architecture that a cleanup can accidentally create:
- a second spine;
- a second state;
- a second goal authority;
- a second artifact registry;
- a second manuscript outline;
- a new project-management layer that conflicts with the existing controls.

### ImprovementCore result

APPROVE the planning task.

Recommended strategy:
repair the organizational control surface around the existing canonical architecture,
starting with exact authority/source mapping before changing any folders.

No phase should modify goals, spine, research object, or manuscript architecture merely to
make the tree prettier.
