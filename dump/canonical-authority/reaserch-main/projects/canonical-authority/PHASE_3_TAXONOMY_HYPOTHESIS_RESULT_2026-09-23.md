# Canonical Authority Phase 3 — Taxonomy Hypothesis Design

Date: 2026-09-23
Status: COMPLETE / KEEP CURRENT LOAD-BEARING TAXONOMY

## ImprovementCore PRE

Models tested:

T1 current hybrid
T2 strong semantic separation
T3 hybrid root-authority + typed support subtrees

## Taxonomy comparison

### T1 — Current hybrid
Strengths:
- keeps load-bearing control objects discoverable at project root;
- research support is already grouped under research/;
- audits are already separated;
- manuscript/control surfaces remain close to project authority;
- historical evidence remains recoverable.

Risks:
- root contains several different operational layers;
- human must learn which root files are authoritative versus derived.

### T2 — Strong semantic separation
Risks:
- increases navigation depth;
- makes path taxonomy look like authority;
- separates load-bearing objects from their existing project-level control context;
- risks duplication of indexes and READMEs;
- offers little strict gain because role distinctions already exist semantically.

Disposition: REJECT for current evidence.

### T3 — Root-authority + typed non-authoritative subtrees
Strengths:
- preserves current authority root;
- allows future organization of large support/audit corpora;
- compatible with existing architecture.

Risk:
- unnecessary until a specific support corpus creates material navigation cost.

Disposition: DEFER pending actual navigation evidence.

## Relational PD result

T1 preserves the highest number of existing source/derived relations with the fewest
path changes.

T2 creates artificial structural relations that do not correspond to semantic ownership.

T3 is a useful future extension but is not yet justified as a portfolio-wide move.

## RepairCore result

No oscillation demonstrated.
No competing taxonomy produces enough gain to justify a migration.

## Human-entry simulation

A new user can reach:
project page → goals/state → research architecture → sources → manuscript → audits.

The remaining friction is explaining this route, not rebuilding it physically.

## ImprovementCore POST / Phase 3 gate

DECISION:
KEEP CURRENT LOAD-BEARING TAXONOMY.

DEFER physical folder restructuring.

The next work is control-surface/human-navigation reconciliation, not folder movement.
