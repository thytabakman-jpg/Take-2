## 2. IC-017 + IC-011 opening preflight

### IC-017 result

The request is not one job. It is a conjunctive publication program with interacting but non-substitutable branches:

1. project control/orientation;
2. corpus/source/provenance closure;
3. novelty/comparator closure;
4. open theory and ceiling raising;
5. manuscript architecture;
6. manuscript drafting;
7. hostile/referee validation;
8. citation/reproducibility closure;
9. venue/framing closure;
10. external researcher/referee handoff.

No branch can silently stand in for another. Drafting does not close provenance. More theory does not close novelty. Source accumulation does not establish corpus adequacy. A polished manuscript does not establish reviewer robustness.

### IC-011 result

The plan must be adaptive rather than a rigid waterfall. At every material state change:

RESOLVE -> MODEL -> LOCALIZE -> SELECT -> GENERATE -> TEST -> PROPAGATE -> RECOMPUTE -> CHALLENGE -> STOP_OR_ESCALATE.

The roadmap therefore defines phases, but phase order can change after a checkpoint. The next phase proceeds only when the checkpoint says REMAINING_PLAN_VALID.

### Capability-selection result

The full backend is useful across the lifecycle, but not every capability belongs in every phase. Running every audit on every object would violate the system we built. The correct "full force" interpretation is:

- expose the whole demonstrated repertoire to selection;
- use every capability whose job is material somewhere in the program;
- use project-local capabilities where they dominate generic machinery;
- use explicit chains rather than isolated tool calls;
- recompute the package after every meaningful phase.

Across this roadmap, the materially relevant repertoire includes A01-A18, I01-I16, T01-T09, HF-001, Multi-Object Connector, Orthogonal Five-Lens PD, ceiling-raising feedback, Practical Research Control, PracticalCore selection, Canonical partial-order priority, Execution Episode, and TransferCore handoff.

   - recursively discover hidden dependencies, bridges, selectors, and representation defects.
4. PRACTICALCORE SELECTION
   - discover jobs and select the bounded capability package.
5. EXECUTE THE PHASE-SPECIFIC CHAIN.
6. INDEPENDENT CHALLENGE
   - use a materially different attack/rival where consequence is material.
7. A16 REGRESSION
   - test the actual successor against protected behavior.
8. IC-017 RECOMPUTE
   - update frontier, OPENs, invalidation set, successor graph, and capability needs.
9. IC-011 ADAPTIVE RESELECTION
   - ask whether the next planned phase is still the highest-leverage live job.
10. TRANSFERCORE
   - capture reusable inbound/outbound discoveries when material.
11. DISPOSITION
   - CONTINUE / NARROW / REORDER / EXPAND / REPLAN / BLOCK / COMPLETE.

No phase is complete merely because its planned operations were executed.
