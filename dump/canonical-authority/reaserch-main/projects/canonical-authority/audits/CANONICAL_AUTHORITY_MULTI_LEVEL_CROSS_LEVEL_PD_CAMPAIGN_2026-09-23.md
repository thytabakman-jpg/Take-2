# RUN C — Gate level

Objects:
PROFILE
TRACE
DISCRIMINATE
RECOGNIZE
COMPOSE
PD

Question: are these genuinely separate jobs, and what dependencies exist?

Results:

PROFILE -> TRACE:
PROFILE supplies typed source/output representation. TRACE presupposes enough PROFILE to identify what is being connected. Existing architecture correctly treats PROFILE as setup rather than independent success conjunct.

TRACE -> DISCRIMINATE:
Direction is strict for the current target. One cannot discriminate P_R/P_N using a source relation that has not been linked to the target. DISCRIMINATE therefore presupposes target-indexed TRACE.

DISCRIMINATE -> RECOGNIZE:
Source-side asymmetry can exist without evaluator e having warranted grounds to identify/use it. Distinct jobs survive.

RECOGNIZE does not feed backward into source-side truth support:
Evaluator recognition can alter usable grounds, not source-attributable discriminatory force.

COMPOSE:
COMPOSE is not simply the final gate in every route. It is conditionally activated only when multiple completed grounds exist. Thus the visual chain PROFILE -> TRACE -> DISCRIMINATE -> RECOGNIZE -> COMPOSE is misleading if read as a mandatory serial pipeline.

Better dependency graph:

PROFILE -> TRACE -> DISCRIMINATE
                       |
                       v
                 completed ground
                       |
RECOGNIZE_e -----------+--> evaluator-usable ground

multiple completed grounds -> COMPOSE_kappa -> case selection

New result:
RECOGNIZE and COMPOSE are not ordinary serial successors. They operate on different bearers:
- RECOGNIZE indexes a completed discriminator to evaluator usability.
- COMPOSE operates over plural completed grounds under a licensed composition specification.

This strengthens the existing distinction and suggests the architecture is a DAG, not a chain.

Gate commutativity:
- PROFILE/TRACE do not commute.
- TRACE/DISCRIMINATE do not commute.
- DISCRIMINATE/RECOGNIZE do not commute in semantic dependency, although recognition evidence can be investigated earlier procedurally.
- RECOGNIZE/COMPOSE are not simply commutable because they operate on different typed objects; composition can be defined source-side or evaluator-relative only after its indexing regime is declared.

Hidden selector:
COMPOSE's kappa remains a selector family. Current robust-selection machinery correctly requires admissibility and selector attribution.

Case verdict unchanged.

# RUN D — Epistemic-component level

Objects:
source identity S
content C
authentication A
reliability R
target linkage L_tau
discrimination Delta
evaluator access/warrant W_e
PD

Results:
A source-to-truth route requires more than one dimension.

A useful factorization is:

S -> C
A authenticates some relation/source/channel
R concerns truth-conduciveness for a proposition/domain/type
L_tau maps the authenticated/reliable content to the target proposition
Delta determines asymmetric bearing on the rivals
W_e makes the discriminator warrantedly usable by evaluator e

Crucial discoveries:

1. Authentication and reliability are orthogonal.
An authentic source can be unreliable for a target; a reliable process can be unauthenticated to evaluator e.

2. Reliability and target linkage are orthogonal.
General reliability on domain d does not establish that the source bears on tau.

3. Content possession and target linkage are distinct.
A source can contain creation knowledge without establishing that the syntactic proposition I_S is part of that knowledge.

4. Evaluator access is downstream of source-side force but can have upstream evidential inputs.
This resolves an apparent circularity: evidence used by e to authenticate a route is not identical to the route's source-side truth relation.

5. The current three-level compression
SOURCE/CHANNEL STATUS -> TARGET LINK -> SELECTION/UPTAKE
is useful but hides authentication/reliability distinctions inside level 1 and discrimination/recognition distinctions inside level 3.

Therefore the three-level compression is reader-useful but not primitive enough for hostile audit.

Candidate audit-level factorization:

SOURCE/CONTENT
-> AUTHENTICATION
-> RELIABILITY-TYPE
-> TARGET LINKAGE
-> DISCRIMINATION
-> EVALUATOR WARRANT

Not every route requires these as six serial stages; they are typed jobs/coordinates.

# RUN E — Result/status level

Objects:
TRUE
BINDING
CANONICAL
LEGITIMATE
RECEIVED
AUTHENTICATED
REASONABLE/ADMISSIBLE
PD

Results:

No general equivalence is licensed among these statuses.

Key relations:
- BINDING does not entail TRUE as a general analytic relation.
- CANONICAL does not entail TRUE.
- LEGITIMATE does not entail TRUE.
- RECEIVED does not entail TRUE without a truth-conducive reception/authentication framework plus target identity.
- AUTHENTICATED does not entail TRUE unless what is authenticated is itself a truth-conducive route/content relation.
- REASONABLE/ADMISSIBLE does not entail TRUE.
- TRUE does not by itself entail BINDING, CANONICAL, RECEIVED, or AUTHENTICATED.

New architecture:
These statuses live on different bearers:
- TRUE primarily predicates propositions.
- BINDING can predicate norms/rulings/practices.
- CANONICAL can predicate texts/interpretations/corpora/status membership.
- LEGITIMATE can predicate positions/practices/interpretations.
- RECEIVED can predicate content/transmission claims.
- AUTHENTICATED can predicate sources/channels/claims/routes.
- REASONABLE/ADMISSIBLE can predicate beliefs, interpretations, inferences, or candidates relative to a regime.

This bearer typing explains many apparent conflicts without needing substantive adjudication.

New principle:
STATUS PORTABILITY requires both bearer conversion and relation licensing. Same word "authority" cannot silently carry a status from one bearer to another.

# Campaign-level discoveries

## D1 — The architecture is typed and non-flat

Sources, functions, gates, statuses, propositions, evaluator states, and composition rules are different object classes. Many apparent "authority" arguments are cross-type transitions.

## D2 — The gate architecture is a DAG, not a simple chain

PROFILE -> TRACE -> DISCRIMINATE forms the source-ground core.
RECOGNIZE indexes completed grounds to evaluators.
COMPOSE conditionally operates over multiple completed grounds.
Treating all five as one serial chain obscures bearer differences.

## D3 — The old function list is also non-flat

F2-F5 are object-output functions.
F6 is a meta-constraint.
F7 is an inquiry-result discipline.

## D4 — Status portability requires bearer conversion plus relation licensing

Authority/status cannot move silently from texts, institutions, channels, rulings, or traditions to propositions.

## D5 — Three-level compression is useful but audit-incomplete

SOURCE/CHANNEL STATUS -> TARGET LINK -> SELECTION/UPTAKE remains useful reader-facing compression.
Hostile audit needs finer typing of authentication, reliability, target linkage, discrimination, and evaluator warrant.

## D6 — Current case obstruction is now maximally localized

The strongest current obstruction is not "no authority" and not "no relevant tradition."

It is:

No licensed CONTENT IDENTITY or CONTENT-TO-TARGET IMPLICATION currently connects the privileged/received creation content to I_S.

## D7 — Search routing improves

Highest-value acquisition targets:
- source evidence that I_S is itself received/esoteric content;
- a source-grounded implication from received creation content to I_S;
- a new independently admissible source package supplying that edge;
- explicit evidence changing the target or admitted inquiry frame.

General authority/status sources have lower expected case-changing value unless they supply one of these.

## D8 — Positive control becomes more important

H_X shows that authority can in principle adjudicate descriptive truth when authentication, target coverage, discrimination, and evaluator recognition are instantiated. Therefore the paper's claim is target-relative and route-relative, not a universal anti-authority thesis.
