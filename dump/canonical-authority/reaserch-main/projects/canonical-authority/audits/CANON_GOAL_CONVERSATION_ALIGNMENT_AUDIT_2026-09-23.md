## Core finding

The current project page correctly puts:

Project Goal -> publish the paper

at the top of the cockpit.

The canonical GOALS.yaml currently makes CANON:G0 a substantive research target:

> Produce a rigorous source-grounded peer-reviewed paper ... to determine what selected second-order Jewish ... structures can legitimately contribute to assessing incompatible truth-apt canonical claims.

The earlier goal-purity audit correctly identified that this sentence bundles:
- substantive research target;
- publication deliverable;
- fixed worked case;
- method/scope;
- quality/evidence controls.

The recent conversation gives us a cleaner practical architecture rather than evidence that the substantive target itself disappeared.

## Reconciled interpretation

Use four distinct control objects:

1. PROJECT GOAL
   Publish a rigorous source-grounded peer-reviewed paper.

2. SUBSTANTIVE RESEARCH TARGET
   Determine what epistemic grounds, if any, are available within Jewish thought for truth-directed assessment of incompatible truth-apt canonical claims when shared canonical standing alone does not adjudicate between them.

3. PROTECTED CONSTRAINTS / INVARIANTS
   Fixed Rashi-Ramban case, second-order scope, spine, source-grounded transfer, purposive non-exhaustive corpus, bounded-result discipline, package TRACE / COMPOSE distinction, evaluator-relative warrant, theory freeze.

4. PUBLICATION-READINESS CONDITIONS
   Source/provenance closure, novelty closure, manuscript execution, journal framing, and eventual external review.

This preserves both the current user's cockpit requirement and the substantive target recovered by the prior audit.

## Important consequence

No immediate goal mutation is justified merely from the recent conversation.

The project-page distinction is the correct immediate repair:
PROJECT GOAL at the top;
SUBSTANTIVE RESEARCH TARGET immediately beneath or in the high-level control layer;
CONSTRAINTS separated explicitly;
publication readiness kept downstream.

If the eventual authoritative goal hierarchy is changed, that requires explicit goal-change authority and propagation.

## New conversation-derived requirement

Every future project-page review should compare:
- current project goal;
- substantive research target;
- current spine;
- current reader/manuscript architecture;
- current user-stated objective in the active conversation.

A mismatch is a review trigger, not permission to silently rewrite the canonical goal.
