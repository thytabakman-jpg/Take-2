## Sort-Later migration principle

Do not drain Sort Later by chronological order.

For each Canonical Authority Sort-Later item:
1. classify its object type;
2. compare it against current canonical state;
3. determine whether it revises, supports, supersedes, creates, or merely records;
4. run the relevant audit/ImprovementCore gate;
5. route it to the smallest authoritative destination;
6. propagate only material downstream effects;
7. remove the item from Sort Later only after durable routing is verified.

## ImprovementCore result

The migration itself must be adaptive.

The highest-leverage first promotion is not "update every file."
It is:
1. settle the semantic spine primitives;
2. settle the project-goal / substantive-target / constraint architecture;
3. regenerate the project-page cockpit;
4. propagate only the validated deltas.
