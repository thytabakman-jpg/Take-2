# Canonical Authority — Whole-Chat Root Cause 001

Date: 2026-09-24
Status: EXECUTED / ROOT SET IDENTIFIED RELATIVE TO RECURRENCE CRITERION
Controller: Improvement Core
Target: recurring failure across the current conversation

## Explanandum F

Across repeated successful tool, audit, architecture, GDOS, routing, liveness, and
blueprint passes, the user still has to ask the system to "really solve the problem."

Most recent symptom:
the assistant called MANUSCRIPT_BLUEPRINT_FINAL_2026-09-24.md the fully completed outline,
but that artifact still contains:
- controller/backend terminology;
- readiness/status machinery;
- tool/liveness rules;
- evidence-owner metadata;
- local population packets;
- explicit unfinished production obligations.

That artifact is a valid internal control blueprint.

It is not yet the simplest author-facing object the user requested:
one complete paper outline that can be read front-to-back, approved, and then populated
with prose.

## Contrast Fbar

A workflow in which:
1. internal research/control architecture is allowed to be complex;
2. its consequences are fully consumed;
3. the terminal handoff produces a separate clean author-facing outline;
4. the author-facing outline contains the substantive paper plan rather than the machinery
   used to construct it;
5. approval of that outline moves directly to prose population unless a genuine reopen
   trigger appears.

## Root criterion rho

Select the smallest upstream recurrence generator whose redesign prevents the repeated
substitution of scaffolding/control work for the requested terminal manuscript-planning
deliverable while preserving the useful internal research/control architecture.

## Candidate causes

C1 — TERMINAL OUTPUT CONTRACT ABSENT / UNDER-TYPED

The system has strong contracts for:
- research objects;
- manuscript controls;
- movements;
- evidence;
- synchronization;
- routing;
- liveness;
- closure.

But it has not frozen a distinct terminal object type:

AUTHOR_FACING_OUTLINE

with a success condition defined by the user's intended review experience.

Role:
ROOT CANDIDATE.

C2 — INTERNAL BLUEPRINT / AUTHOR OUTLINE CONFLATION

MANUSCRIPT_BLUEPRINT_FINAL performs several internal jobs:
- research-to-manuscript control;
- movement readiness;
- claim lifecycle;
- evidence routing;
- production routing;
- reopen/liveness control.

The user-facing outline job is only one of those.

Role:
PROXIMATE CAUSE and consequence of C1.

C3 — TOOL-CENTERED COMPLETION CREDIT

Each new tool wave is considered successful when it yields a valid structural/control
delta, even when that delta does not change the terminal author-facing artifact.

Role:
PROPAGATION MECHANISM.

C4 — WHOLE-PROJECT TARGET EXPANSION

When the target is "the whole project," high-power tools correctly discover more backend
structure. Without a terminal handoff contract, those discoveries repeatedly become new
work rather than being filtered by whether they alter the author-facing plan.

Role:
ENABLING / AMPLIFYING CONDITION.

C5 — META/FAST TIMESCALE LEAK

The system now formally distinguishes fast drafting work from meta architecture, but the
conversation still allows every new tool wave to reopen meta work before the terminal
author-facing outline has been delivered.

Role:
RECURRENCE MECHANISM.

C6 — "FINAL" LABEL USED BEFORE USER-LEVEL TERMINALITY

Files have been labeled final/frozen because architecture was relatively closed, while the
user-level job "show me the completed outline I can approve" remained unsatisfied.

Role:
SYMPTOM / NAMING FAILURE.

## Counterfactual tests

Repair C6 only:
rename files.
Result:
does not prevent future scaffolding substitution.

Repair C3 only:
require root-effect gating for new tools.
Result:
helps, but the root effect remains under-typed because the terminal author-facing object
is not defined.

Repair C4 only:
use narrower targets.
Result:
reduces expansion but does not tell the system when internal work has completed the
user-facing deliverable.

Repair C2 only:
manually rewrite the current blueprint.
Result:
can solve this instance but recurrence remains likely for future projects.

Repair C1:
define a distinct AUTHOR_FACING_OUTLINE object with:
- purpose;
- required contents;
- forbidden internal/control contents;
- acceptance criteria;
- source-of-truth inputs;
- terminal handoff semantics;
- reopen contract.

Then route all internal tools into that object only through material effect.

Expected:
internal architecture can continue to exist without appearing in the author-facing outline;
new tool waves cannot claim terminal completion unless the author-facing artifact is updated
or certified no-effect.

## Root result

Relative to rho:

Root_rho(F) = {C1}

C1:
the workflow lacks a canonical terminal author-facing outline contract and handoff boundary,
so internal control/architecture artifacts repeatedly substitute for the requested final
paper-plan deliverable.

## Repair implication

Do not delete or flatten the internal blueprint.

Instead create:

AUTHOR_OUTLINE_CONTRACT
AUTHOR_OUTLINE_FINAL

with relation:

Research/Control System
-> internal manuscript blueprint
-> AUTHOR-FACING PROJECTION
-> user approval
-> prose population.

The projection must remove:
- tool names;
- controller mechanics;
- artifact governance;
- liveness machinery;
- status-taxonomy detail not needed for author review.

It must preserve:
- paper goal;
- thesis/question;
- exact section structure;
- subsection/movement purpose;
- substantive claims;
- source/evidence placement at the level needed for author decisions;
- transitions;
- what each section earns;
- explicit remaining decisions only when they truly cannot be made yet.

## Root-cause verdict

UNIQUE RELATIVE TO CURRENT MODEL + rho.

Root:
missing terminal author-facing outline contract / handoff boundary.
