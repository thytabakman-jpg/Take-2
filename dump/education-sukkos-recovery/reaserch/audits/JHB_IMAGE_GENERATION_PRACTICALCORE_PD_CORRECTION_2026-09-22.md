## PD Audit 1 — A18 / HF-001 historical recursive PD bootstrap

### Reconstructed state transitions

Historical production repeatedly moved through two materially different modes:

A. BOOKLET CREATION / MAJOR RECOMPOSITION
shared four-page concept
→ simultaneous/coordinated generation
→ strong style/sequence coherence when successful
→ occasional topology/page-identity collapse.

B. BOOKLET REPAIR
mostly useful existing page
→ bounded removal/replacement/inpainting
→ successful preservation of surrounding state
→ much lower collateral redesign than full regeneration.

The earlier protocol incorrectly collapsed these modes into one universal single-page strategy.

### Hidden dependencies surfaced

1. Generation-episode cardinality and output-object topology are different coordinates.
   A request can be one coordinated episode while still requiring four separate full-size outputs.

2. Shared generation context is a positive resource.
   It can preserve visual grammar, rhythm, relative density, and cross-page progression better than unrelated page-by-page calls.

3. Page identity must be explicit inside a batch.
   Merely requesting "four pages" does not guarantee Page 1, Page 2, Page 3, Page 4. Without separate page contracts the generator can return four variants of the same concept.

4. Salvage is distinct from regeneration.
   A partially successful four-page batch does not justify discarding the whole set. Successful pages become protected state; failed pages enter local repair.

5. The workflow needs both set-level and page-level state.
   Page blueprints alone do not encode booklet coherence. A booklet batch manifest is required.

6. Exact content and visual rendering are separable.
   A visually successful page with one text or local-object defect can be repaired locally rather than resampled globally.

### HF-001 result

The load-bearing architecture is phase-sensitive:

COORDINATED BATCH GENERATION
→ SET-LEVEL VERIFICATION
→ FREEZE SURVIVORS
→ LOCALIZED REPAIR
→ FINAL SET VERIFICATION.

A one-canvas contact sheet is not the same object.

## Correct production architecture

### Phase 0 — Freeze content and objects

Before generation, have:
1. exact Fick source/working-set binding;
2. four-page route map;
3. booklet batch manifest;
4. shared visual/style contract;
5. four exact page blueprints;
6. asset pack;
7. acceptance matrix.

### Phase 1 — Coordinated four-page generation

Use one coordinated generation episode for the four-page set when making a major revision or rebuild.

The generation contract requires:
- four distinct outputs;
- one output assigned to each PAGE_ID;
- each output full-size;
- no contact sheet;
- no composite four-panel sheet;
- no repeated page variants;
- common booklet visual grammar;
- page-specific content and job.

### Phase 2 — Batch verification

Check:
- exactly four page objects exist;
- P1/P2/P3/P4 are all represented once;
- shared visual language is coherent;
- page jobs differ correctly;
- progression is intact;
- no later concept leaks early.

### Phase 3 — Freeze survivors

For every page that passes:
- freeze the render as protected state;
- do not regenerate it merely because another page failed.

### Phase 4 — Surgical repair

For failed pages:
- first prefer region-level repair;
- then page-level repair;
- rerun the full four-page batch only when the defect is booklet-level or shared-style/route-level.

### Phase 5 — Final set verification and packaging

Recheck both page-level and booklet-level acceptance.
Package only after the four-page set passes.

## Immediate Fick consequence

The next Fick revision should not begin by independently generating Page 1, then Page 2, then Page 3, then Page 4.

Build the complete four-page generation package first.

Then run a coordinated four-page generation episode with four distinct page outputs.

If three pages succeed and one fails, freeze the three and surgically repair the fourth.

That architecture preserves both observed successes rather than sacrificing one to protect against the other's failure mode.
