## Findings

### JHB-AUD-001 — Authority status is underspecified

Severity:
HIGH FOR CONTROLLED OPERATION

The header calls the file a "source-grounded operating control."

But repository architecture does not currently define MASTER_CONTROL.md as an authoritative project layer.

PORTFOLIO.yaml still classifies the project as reconstructed/provisional.

GOALS.yaml remains provisional.

Therefore "operating control" can be read more strongly than repository authority semantics currently license.

Repair:
Define MASTER_CONTROL as authoritative for the migrated non-goal educational/control layer once explicitly registered, while leaving goal identity under GOALS.yaml and GOAL_CHANGE_POLICY.md.

Until registration, use candidate/source-grounded control language rather than implying full project canonicality.

### JHB-AUD-002 — Stable rule identity was lost during consolidation

Severity:
HIGH FOR REPEAT AUDIT / CYCLE DETECTION

Earlier project-state material used stable identifiers such as INV-001 through INV-029 and booklet-local findings.

MASTER_CONTROL preserves much of their substance but mostly converts them back into prose.

This causes information loss for repeated audits.

Without stable rule/finding IDs it is harder to tell whether:
- a rule changed;
- a finding recurred;
- a repair reopened a prior invariant;
- two differently worded findings are semantically the same.

Repair:
Add a stable control-invariant register and a stable current-finding register.

Do not require every sentence to receive an ID; assign IDs to load-bearing reusable rules and active findings.

### JHB-AUD-003 — Typed route graph is declared but not instantiated

Severity:
HIGH FOR RELATION-LEVEL AUDIT

Section 20 correctly states that the project is a branching dependency graph and defines relation types.

But the four booklet routes remain primarily prose arrows.

The artifact therefore says relations must be typed without actually storing the current relations in typed form.

This is especially load-bearing for Conservation, whose live defect is itself a cross-domain relation-type problem.

Repair:
Instantiate a typed edge register for the current four booklet routes containing at least:

source
target
relation
preserved content
new content
basis/status

The register can remain human-readable Markdown.

### JHB-AUD-004 — Evidence identity is source-level but incomplete at artifact level

Severity:
MEDIUM / BLOCKS SOME VERIFICATION, NOT ARCHITECTURE RECOVERY

### JHB-AUD-006 — Whole-file convergence and layer-specific convergence are not distinguished

Severity:
HIGH FOR THE USER'S CURRENT CONTROLLED-AUDIT PURPOSE

MASTER_CONTROL contains both:

1. relatively stable reusable architecture/governance;
2. volatile current booklet states and open fronts.

A legitimate Fick or Conservation state update changes the whole file even when the shared architecture remains unchanged.

Without audit domains, a later whole-file audit can blur:
- architecture convergence;
- booklet-state convergence;
- empirical convergence;
- provenance convergence.

Repair:
Define audit domains, for example:

A — project identity/scope
B — shared four-page architecture
C — source/science/activity rules
D — artifact/production/repair governance
E — booklet-specific state
F — evidence/provenance
G — empirical state

Every audit finding should identify its domain.

Convergence can then be claimed per domain as well as for the whole artifact.
