## 3. Project identity

This is a bounded Jewish education production project for Grade 5-6.

The target is not a universal theory of curriculum.

The reusable architecture here is a house architecture for this booklet family.

Its job is to support four usable student-facing holiday booklets in a one-session classroom setting.

General educational theory is relevant only when it materially advances, repairs, validates, or protects this booklet work.

## 4. Why four pages

The four-page form is a project constraint and house form, not a universal pedagogical law.

The current reasons for retaining four pages are project-specific:

- the booklets are designed as bounded one-session student-facing artifacts;
- the user has repeatedly preferred the compact four-page physical form;
- four pages provide enough room for four distinct major inquiry moves without turning the artifact into a long workbook;
- the form supports a visible progression from encounter to usable transfer;
- each page can carry one coherent major learner move while still containing several inseparable functions;
- the completed Yom Kippur artifact demonstrates that the form can work as a real booklet rather than only as an abstract architecture.

Do not infer that every successful curriculum needs four pages.

Do not infer that four pages must always have one universal four-label grammar.

Need -> Tool -> Transformation -> Agency remains a useful candidate abstraction, not a proven invariant.

For this holiday family, the more specific working archetype is stronger.

## 5. Shared four-page holiday architecture

The four physical pages form one learner transformation, not four neighboring mini-lessons.

The governing movement is:

real phenomenon or structured encounter
-> human problem
-> usable Jewish conceptual operation
-> holiday embodiment or deepening
-> enactment
-> independent transfer

Six functions can be compressed into four pages because one page can perform several inseparable functions while still making one coherent major learner move.

### Page 1

Job:

Create a real encounter with the world that earns a human question.

Typical resources:

- science;
- mathematics;
- a structured phenomenon;
- a concrete contrast.

The science or mathematics must perform genuine intellectual work.

It is not a decorative metaphor pasted onto a preselected lesson.

The learner must leave Page 1 able to notice or ask something that was not available before.

Page 1 hands off a bounded human problem.

### Page 2

Job:

Give the learner a usable Jewish conceptual operation that answers or reorganizes the human problem.

The Page 2 Jewish material must do real work independently of the holiday reveal.

A source cannot function merely as decorative authority.

A useful Page 2 operation can be:

- a distinction;
- a practice;
- a model;
- a way of attending;
- a way of deciding;
- a structured response.

The strong hinge test is:

1. Does the Jewish concept exist meaningfully without Sukkos or Yom Kippur?
2. Does it give the learner a usable operation?
3. Does it actually address the Page 1 human problem?
4. Is source content separated from interpretation and educational application?

### Page 3

Job:

Reveal or deepen the holiday as an embodied realization of the same operative structure.

Page 3 does not merely illustrate Page 2.

The holiday must add something unavailable from the generic human lesson alone.

For Sukkos, the key test is not merely:

"Can I mention a sukkah here?"

It is:

"What does Sukkos physically, legally, temporally, communally, or ritually make available that Page 2 did not?"

The strong replacement test is:

If Sukkos were replaced by a generic activity, would something educationally important be lost?

If nothing important is lost, Page 3 is probably illustration rather than holiday embodiment.

### Page 4

Job:

Require independent use.

The learner applies the distinction or operation to a new case, makes a bounded choice, designs a response, or identifies an action.

Page 4 cannot merely ask the learner to repeat the lesson language.

It must test transfer.

Personal disclosure remains optional.

## 6. Hinge architecture

The project repeatedly discovered that the critical structure is not simply P1 -> P2 -> P3 -> P4.

The strongest route test is:

human problem
-> Jewish operation
-> holiday embodiment
-> independent transfer

For the Page 2 to Page 3 hinge, test:

- independent Jewish reality;
- holiday nativeness;
- operative identity;
- embodied surplus;
- replacement failure;
- source / interpretation / application separation;
- Page 4 continuity.

A coherent route can still fail when two neighboring pages use related vocabulary but perform different operations.

Do not accept thematic similarity as operative continuity.

## 7. Page as causal learning unit

Each page is a causal unit in the learner route.

A useful page-internal model is:

entering learner state
-> shared encounter
-> notice
-> public question
-> participant reasoning or action
-> new shared understanding

Each page must be locally complete enough to accomplish a real move.

Each page must also generate or earn the next question.

The page transition is not justified merely because the author knows what comes next.

Required bridges must be available to the learner.

Cross-page dependencies can extend beyond the immediately previous page.

Terms, activities, examples, visual framing, and distinctions can create dependencies that need to be tracked across the booklet.

## 8. No hidden facilitator intelligence

This project is designed around structured shared inquiry.

The public system is:

public artifact
+ public shared encounter or activity
+ participant reasoning/action
-> new shared understanding

There is no privileged teacher or facilitator curricular-information role.

An adult can manage:

- time;
- safety;
- materials;
- people;
- logistics;
- conversation process.

The adult cannot carry a hidden conceptual bridge required for the lesson to work.

Cold-start reproducibility is therefore a project requirement.

Learners using the artifact together should be able to proceed meaningfully without a private teacher script.

Reproducibility does not mean every group has the same conversation.

It means the required conceptual route is publicly available.

A redesign trigger exists when the intended insight appears only after an adult explains what the artifact failed to make available.

## 9. Source discipline

For every important Jewish source keep distinct:

source content
-> interpretation
-> educational application

A source can ground the project without directly teaching the final student-facing application.

Do not convert an educational analogy into a claim that the source itself states that analogy.

Do not use source prestige to substitute for a missing bridge.

Use scholarly apparatus in proportion to the learner-facing job.

The student-facing artifact can be simple while the backend source boundary remains precise.

## 10. Science and analogy discipline

Real mathematics and science must do genuine work.

The project does not permit:

science term
-> similar-sounding human slogan

as a sufficient bridge.

Instead ask:

- What exact structure is established in the scientific domain?
- What question does that structure make available?
- What content survives when moving into the human domain?
- What new purposive, normative, psychological, or Jewish content enters later?
- Is the learner being told the analogy boundary?

People are not materials.

Experiences are not light.

Human convergence is not diffusion.

A scientific relation can generate a problem, contrast, or structural possibility without dictating a human norm.

## 11. Activity discipline

An activity counts only when it changes learner state or lets the learner use a distinction already developed.

Craft completion is not enough.

Physical enactment must expose or exercise the conceptual operation.

Enactment is not established practice.

A plan is not established practice.

A one-time successful group action is not evidence that a durable habit has formed.

For current Sukkos booklets, edible-sukkah construction is a fixed project requirement and must perform conceptual work.

The edible build is not decorative.

## 12. Observable learning evidence

Every major learner-state transition needs an observable test.

For each transition distinguish:

- intended evidence;
- plausible false positive;
- likely failure pattern;
- what the failure would diagnose.

Observed target performance does not by itself identify the causal mechanism that produced it.

A learner can reach the right answer through prior knowledge, social imitation, ordinary reasoning, or a different scaffold.

Therefore empirical success and mechanism validation remain distinct.

## 13. Visual and artifact system

Visual teaching is part of the curriculum.

Images and layout can:

- direct attention;
- make relations inspectable;
- separate domains;
- scaffold comparison;
- support memory;
- create writing/action space;
- regulate density and pacing.

Visuals are not decoration added after the curriculum.

At the same time, visual style is separable from curricular function.

Current house-fit preference:

- conversational;
- elegant;
- non-condescending;
- visually coherent;
- developmentally accessible without looking childish.

This is a series/author preference, not a universal pedagogical rule.

Page function determines composition.

The four pages do not need identical layouts.

Unity comes from a stable visual language across pages, not from making every page look the same.

The exact scope of the visual-style profile remains open.

## 14. Artifact realization

The realization sequence is:

learning architecture
-> artifact specification
-> rendered artifact
-> participant experience

with feedback when a later layer fails.

An artifact specification is a functional contract.

It states what each element:

- contains;
- must preserve;
- must accomplish.

Correct content can still be represented badly.

Artifact audit therefore asks whether the public representation actually carries the intended curricular functions.

Relevant dimensions include:

- native-domain accuracy;
- framing;
- inference preservation;
- attention;
- conversation;
- emotional function where relevant;
- usability;
- integration across pages.

Local page success does not establish whole-booklet success.

## 15. Production and render QA

Production is gated realization.

Production begins only after the relevant upstream architecture and student-facing artifact specification are sufficiently stable.

Production tools do not receive authority to invent curriculum.

Where useful, establish a cross-page visual master or equivalent concrete exemplar before generating individual pages.

After page production, recombine the entire booklet and inspect it again as one object.

Render QA is distinct from artifact audit.

Render QA asks whether the approved specification was implemented faithfully.

Render fidelity can fail independently in:

- text;
- structure;
- page identity;
- conceptual/visual-system preservation;
- whole-booklet coherence.

## 16. Existing-artifact repair governance

A demonstrated defect licenses repair of the implicated frontier.

It does not authorize a clean rebuild of the whole artifact.

The operative repair baseline is the last artifact explicitly accepted for use, continuation, or revision.

The newest generated file is not automatically the baseline.

Operation mode must be classified before production:

### GREENFIELD BUILD

No accepted baseline exists.

### CONSTRAINED REPAIR

An accepted baseline exists and whole-object replacement has not been independently authorized.

This is the default for an existing accepted booklet.

### AUTHORIZED REBUILD

A baseline exists, but independent grounds authorize whole-object replacement.

A defect alone is not enough.

Clean-sheet reconstruction during an audit is diagnostic unless rebuild authority is separately established.

## 17. Preservation and delta control

For constrained repair:

1. freeze the accepted baseline;
2. state the demonstrated defect set;
3. test materially different admissible representations of the defect frontier;
4. classify proposed changes as robustly implicated, representation-sensitive, or not implicated;
5. build a preservation ledger;
6. write a delta specification;
7. edit only the authorized delta;
8. compare the repair against the baseline;
9. require defect resolution and non-regression;
10. run author / house-fit inspection separately;
11. keep empirical validation separate.

Preservation statuses include:

- VERIFIED FUNCTION;
- AUTHOR-ACCEPTED / HOUSE-FIT;
- PRESUMPTIVELY RETAINED;
- DEFECT-LINKED / OPEN.

Do not infer:

not inferentially necessary
-> safe to delete

because an element can be instructionally, experientially, or identity/preservation load-bearing.

Production may choose only among variables explicitly left FREE.

Silence is not permission to redesign.

## 18. Readiness vocabulary

### Architecture-ready

The causal learner route and source roles are coherent enough for artifact work.

### Artifact-ready

The public representation is specified at sufficient functional resolution.

For repair, this additionally requires:

- baseline;
- defect set;
- localization;
- preservation obligations;
- delta;
- representation constraints;
- explicit free variables.

### Render-ready

Text, visual obligations, layout constraints, and production method are locked tightly enough that production need not invent material curriculum choices.

### Repair-integrity pass

The defect is fixed, changes are authorized, and preservation obligations are met or explicitly traded off.

### Author / house-fit pass

The resulting artifact fits the intended voice, density, pacing, visual identity, and use.

This is not empirical learning evidence.

### Empirically validated

Real use supports the intended learner transitions and activity mechanics.

These statuses are not interchangeable.

## 27. Repair-cycle protection

This project follows the global `REPAIR_ESCALATION_POLICY.md`.

Do not allow iterative booklet repair to alternate indefinitely between defects.

A cycle is detected when:

- a previously repaired booklet finding reappears because of a later repair;
- repairing one page/hinge breaks another and repairing the second recreates the first;
- the project returns to a materially equivalent earlier repair-state signature;
- the same preservation conflict recurs;
- the defect repeatedly moves between neighboring pages, representations, or route nodes.

When that happens:

1. freeze the cycle trace;
2. stop local edits;
3. preserve all cycling states as evidence;
4. identify the smallest shared upstream structure capable of generating the failures;
5. move the audit one level upward;
6. do not resume local repair until the higher-level audit identifies the conflict, missing distinction, relation error, representation problem, or incompatible requirement.

Examples for this project:

- Page 2 and Page 3 repeatedly break each other -> audit the Page 2/Page 3 hinge, not either page alone.
- A science correction repeatedly damages the human bridge, and restoring the bridge corrupts the science -> audit the cross-domain relation and preserved/new-content boundary.
- Visual repair repeatedly damages page function, while restoring page function repeatedly breaks visual coherence -> audit the artifact-specification/visual-realization interface.
- Two booklet requirements cannot be satisfied together -> audit the shared series constraint or requirement set.
- Multiple booklets exhibit the same alternating failure -> audit the shared holiday architecture rather than patching each booklet independently.

Every repair reruns a regression matrix covering the targeted defect, previously passed invariants in the affected closure, protected functions, and prior findings capable of reopening.

A cycle is evidence about the architecture.

It is not permission to keep trying local variants.

If the higher-level issue turns out to require changing a canonical goal, scope, success condition, or hierarchy, the goal remains unchanged until explicit approval under `GOAL_CHANGE_POLICY.md`.

## 34. Audit-target validity rule

An audit result is valid only for the object it actually audited.

Distinguish:

- PROJECT_ARCHITECTURE_AUDIT
- CONTROL_ARTIFACT_AUDIT
- SOURCE_ARTIFACT_AUDIT
- DERIVED_ARTIFACT_AUDIT
- CANDIDATE_ARTIFACT_AUDIT
- HISTORICAL_RECONSTRUCTION_AUDIT

A control-level audit can establish properties of the project representation without establishing pixel-level or layout-level properties of the accepted booklet pages.

A PDF-level audit can establish properties of that PDF without automatically establishing properties of the accepted source page images.

When an earlier audit used the wrong artifact class, preserve its findings only at the level actually supported and rerun the artifact-specific parts against the exact accepted source set.
