## 3. The failure family that triggered this work

The repeated problem was not merely wording quality.

The project repeatedly reached a state where:

1. the architecture was discussed and improved in chat;
2. exact wording was generated in chat;
3. visual work was planned or generated later;
4. the later stage had no single durable exact-copy object to consume;
5. text could therefore be reconstructed, paraphrased, omitted, or replaced from memory,
   an older PDF, a nearby candidate, or the wrong current page set;
6. candidate identity, accepted-baseline identity, and current-working identity could be
   conflated;
7. improvements made in one conversation were not reliably propagated into the next
   production object.

The deeper control defect was therefore:

`audited concept != exact durable copy != visual specification != render`

Those layers must remain distinct and explicitly connected.

## 4. Current Fick target and learner route

Target learner capability:

A learner can preserve genuine difference, identify what remains shared, coordinate only
what shared activity requires, and continue without forcing sameness everywhere else.

Current route:

diffusion and concentration difference
-> human convergence question
-> difference / sharedness / required coordination
-> one shared sukkah built under common criteria
-> transfer to an unresolved disagreement

Operational spine:

DIFFERENCE
-> SHARED
-> COORDINATE
-> CONTINUE WITHOUT FORCED SAMENESS

The later semantic preflight sharpened this into several protected distinctions:

- difference is an umbrella and different kinds of difference do not generate identical
  consequences;
- shared means a specific relationship, activity, object, goal, situation, or decision
  space, not vague commonality;
- agreement and coordination are distinct;
- required coordination means a common decision or compatible action made necessary by
  the shared activity;
- unresolved does not mean irrelevant, harmless, ignored, or false;
- Rav Kook's source-side contribution is non-uniformity within peace, not the full
  classroom procedure;
- selective coordination is the booklet's educational operation, not a quotation or
  native Rav Kook procedure.

## 5. Learner-state architecture recovered in this conversation

The conversation explicitly distinguished two architectures that had previously been
handled separately:

A. learner-state transformation
B. page/component/image jobs

The old recursive PD comparison showed that these are two views of the same engineered
transition.

Unified causal form:

STUDENT STATE
-> EXPERIENCE
-> NOTICE
-> INFER
-> NAME
-> TEST OR USE
-> NEW STUDENT STATE
-> NEXT LIVE QUESTION

This means wording, images, questions, sources, activities, layout, and handoffs are not
independent design layers. Each must perform a causal role in the learner transition.

### Page 1 state change

Before:

Difference, interaction, convergence, agreement, and coordination are not yet clearly
separated.

Experience:

The learner sees unequal concentrations, random bidirectional particle motion, and a net
diffusive flux.

Discovery:

Interaction can occur while difference remains.

Domain-specific science:

In the simple diffusion setup, redistribution reduces the concentration difference over
time.

Critical boundary:

People are not particles. Physics generates the human question; it does not answer it.

Exit question:

Do people have to become more alike to keep doing something together?

### Page 2 state change

Before:

The learner has a human convergence question but no usable distinction.

Experience:

"Wait... you really believe that?" creates the felt problem. A real disagreement begins
to alter how one person sees another.

Jewish contribution:

Rav Kook supplies the possibility that peace does not require uniformity.

Educational operation:

- What is actually different?
- What is still shared?
- What do we actually need to decide together?
- What can stay different?

Critical distinction:

The operation does not decide who is right. It identifies what the shared situation
requires.

Worked discriminator:

The same pineapple disagreement produces different coordination requirements when the
students order separate slices versus one shared pizza.

Exit question:

What happens when we actually have to build one thing together?

### Page 3 state change

Before:

The learner understands the distinction conceptually but has not used it under real
coordination pressure.

Sukkos contribution:

The shared-sukkah image makes sharedness physical and specifically Jewish.

Source anchor:

Sukkah 27b, "All Israel are fit to sit in one sukkah."

Source/application boundary:

The Gemara discusses sukkah. The classroom build is an educational application of the
shared-sukkah image, not a claim that the sugya itself presents a theory of conflict
resolution.

Experience:

Different design preferences meet one material set and one shared edible sukkah model.

Live prompts:

- Do we need one shared decision here?
- Can this stay different?

Debrief:

- What stayed different?
- What did we have to decide together?
- What did we still build together?

Important HF-001 repair:

Do not tell students the debrief conclusion before they have the experience. Page 3 must
produce the inference, not announce it.

### Page 4 state change

Before:

The learner has successfully used selective coordination in a scaffolded construction
task.

Experience:

A new safe real or invented disagreement with less scaffolding.

Listening support:

Say the other person's view back and ask, "Did I understand you?"

Transfer prompts:

- What is different?
- What are you still sharing or doing together?
- Where do you actually need one decision or coordinated next step?
- What can stay unresolved?
- What can you do next?

Dissolving-paper target:

"WE HAVE TO AGREE ABOUT EVERYTHING BEFORE WE CAN KEEP GOING."

The disagreement does not dissolve.

The demand for total agreement does.

Final capacity:

The student can continue a shared activity without requiring agreement on everything.

## 6. Image and page-job architecture

A key discovery in this conversation was that every significant visual must answer:

"This image exists because the student needs to ______."

### Page 1 central visual job

Make simultaneously visible:

- unequal concentrations;
- random motion both ways;
- net diffusive flux toward lower concentration;
- difference still existing while diffusion occurs.

The image is evidence, not decoration.

### Page 2 central visual job

Make visible the relational change caused by a disagreement:

"They believe X"
-> "Wait... what does that say about them?"

The image supports the felt problem before the tool arrives.

The visual must not reduce the page to generic diversity or generic respectful dialogue.

### Page 3 central visual job

Not merely:

"different people happily in one sukkah."

Instead:

different design preferences
+
one shared structure
+
some choices that can coexist
+
some choices that force one shared decision.

The student must be able to see selective coordination.

### Page 4 central visual job

Show two genuinely different positions alongside a still-shared relationship, activity,
or task.

The dissolving-paper visual must depict the removal of the total-agreement demand, not
the removal of either view.

## 11. Exact-copy control problem and solution

The user explicitly caught the following failure:

Even after all this wording work, there was no single actual document containing the
new final words.

The first proposed repair was:

create `EXACT_COPY.md`, mark it candidate, then later change its status to frozen.

HF-001 plus the ImprovementCore pass found a further hidden defect in that plan.

A single mutable file whose status changes from candidate to frozen can later be edited
while still being treated as the same frozen object.

That would recreate referent/version drift.

The improved solution now implemented is:

audited wording
-> mutable candidate object
-> explicit user approval
-> new immutable versioned frozen snapshot
-> visual spec bound to frozen path + blob
-> render bound to the same frozen path + blob.

Current candidate object:

`JHB:FICK:COPY:CANDIDATE:001`

Current control file:

`projects/jewish-holiday-booklets/fick/COPY_CONTROL.yaml`

Freeze contract:

- explicit user approval is required;
- approval creates a new versioned file such as `copy/EXACT_COPY_v1.md`;
- the frozen snapshot is not edited in place;
- later wording changes create a new candidate;
- later approval creates a new immutable frozen version;
- visual production may arrange/style the frozen text but may not rewrite, paraphrase,
  omit, or add student-facing wording.
