## Task contract

Protected behavior:
- accepted repair baselines remain authoritative for preservation/regression
- candidates never become accepted merely by being newer/current/easier to retrieve
- exact-object preflight remains fail-closed
- parallel workstreams can diverge without overwriting one another
- explicit current-turn user designation controls the current task referent without silently changing global acceptance
- fresh conversations can resume durable substantial work without broad reconstruction
- multiple unresolved live continuations remain OPEN rather than being guessed
- search retrieves bytes only after target/authority resolution
- user-visible presentation consumes the exact resolved target

## AuditCore results

### A01 — task/object typing

The immediate target is not "the Fick artifact" and not "artifact authority".

The target is the cross-layer target-resolution interface that binds a task to the exact object(s) needed for that task.

Distinct typed objects:
1. TaskBinding — request-local referent resolution
2. ContinuationBinding — durable scope-relative working state for substantial continuing work
3. ArtifactObject/ArtifactSet — immutable registered object identity
4. ArtifactAuthorityState — accepted/candidate/rejected/superseded
5. Representation — PNG/PDF/composite/editable source
6. Promotion/TransitionEvent — durable state-changing event

### A02 / A12 — hidden dependency and spine reconstruction

Current operative spine starts too late:

project/booklet -> artifact authority -> exact object -> retrieval.

Required spine:

utterance
-> request predicate
-> request-local TaskBinding
-> continuation/workstream lookup when needed
-> project adapter / role resolution
-> authority constraints
-> exact object-set resolution
-> freshness/conflict validation
-> retrieval/presentation
-> optional durable transition capture.

The hidden dependency is a typed task-to-object binding before the existing ARTIFACT-TO-PRODUCTION interface.

### A03 / A05 — representation attack and invariant localization

Counterexamples:
- one booklet-global active_working_set fails two simultaneous branches
- workstream-only binding fails ordinary current-turn read-only tasks because WORKSTREAM_POLICY explicitly says not every conversation becomes a workstream
- artifact-authority-only binding returns accepted baseline when the user means a live candidate
- filename/search/recency binding recreates the original failure
- making every current-turn selection durable over-mutates project state

Robust affected frontier:
conversation/task bootstrap <-> workstream continuation <-> artifact resolution interface.

The artifact registry itself is not the primary defect.

### A06 — rival reconstruction

R1: global booklet active_working_set.
Rejected: branch collision and false serialization.

R2: workstream-local continuation only.
Improves concurrency but insufficient for ordinary non-workstream tasks and explicit current-turn corrections.

R3: new universal persistent target-binding registry.
Functionally plausible but creates a new state authority and duplicates existing Workstream/Material Event machinery.

R4: two-tier binding using existing architecture.
- ephemeral TaskBinding for every execution
- durable ContinuationBinding only for substantial continuing work
- ARTIFACTS owns immutable identities
- WORKSTREAMS owns substantial branch context
- Material Event/transition controls own durable promotion
- generated JHB workbench joins these sources
Selected.

R5: portfolio-wide universal router.
Potential later generalization; too broad for the demonstrated repair.

### A07 / A08 — provenance and referent continuity

"The user selected these pages for this task" and "these pages are the accepted product" are different propositions with different authority.

The system must preserve:
- source of task binding
- source of continuation binding
- artifact acceptance basis
- lineage/version

"current Fick", "accepted Fick baseline", "the Fick from the ZIP", and "final accepted Fick" are not aliases until a typed binding establishes equivalence for the requested operation.

### A09 — recurrence root

Smallest supported generator:

CONTEXTUAL REFERENT / TARGET BINDING IS NOT A FIRST-CLASS INTERFACE.

The repository models object identity and artifact authority more strongly than it models task-relative reference.

Static durable state without scoped continuation semantics is a manifestation of this generator, not the most general statement of it.

### A10 — historical reconciliation

Prior JHB canonical-state work already required:
- one authoritative home for current semantic state
- transactional updates
- parallel branching
- conflict detection
- explicit unresolved alternatives
- new-chat continuation without reconstruction

The present failure shows incomplete implementation/composition rather than a newly discovered project goal.

### A13 — layered-control map

Existing layers are mostly sound:
- conversation/task intent
- workstream/concurrency
- project/booklet state
- artifact registry/authority
- retrieval transport
- production/repair
- presentation
- material-event closure

Missing interface:
TASK / CONTINUATION -> ARTIFACT TARGET.

Existing IFACE:ARTIFACT-TO-PRODUCTION starts after the missing selection step.

## ImprovementCore results

### I01 / I12 — live frontier and leverage

Highest-leverage frontier:
the task/continuation-to-artifact interface, upstream of JHB retrieval and production.

Do not redesign the learner architecture or accepted artifact registry.

### I02 — successor generation

Survivors:
A. HM-001 pass-2 continuation binding
B. two-tier TaskBinding + ContinuationBinding using existing controls
C. portfolio-general target resolver

B strictly improves A on branch safety and task-local corrections.
C remains a possible later generalization but is not required to solve the demonstrated problem.

### I03 — ceiling raising

Stronger successor B adds:
- current-turn precedence without durable mutation
- durable continuation only when persistence/concurrency risk earns it
- explicit OPEN result for ambiguous fresh-chat continuation
- typed interface contract between task/workstream and artifact target
- no new global state owner

### A17 / I04 — bounded repair frontier

Change only the interface and join surfaces required for target resolution.

Candidate repair:
1. Add an interface contract analogous to IFACE:TASK-CONTINUATION-TO-ARTIFACT.
2. Extend substantial WORKSTREAM records with exact target/baseline bindings where artifact-sensitive.
3. Extend JHB generated bootstrap to accept operation/predicate and optional workstream/continuation context.
4. Construct an ephemeral TaskBinding for every request.
5. Resolve precedence:
   a. explicit current-turn designation
   b. explicit selected workstream/continuation
   c. one promoted/default project continuation when unambiguous
   d. OPEN / one targeted clarification
6. Keep artifact class/acceptance in ARTIFACTS, never in TaskBinding.
7. Record durable promotion only through material-event/transition machinery.
8. Make packaging and display consume the resolved TaskBinding/set ID rather than reselecting.

### I09 / I10 / I11 — interface, decomposition, cross-layer

Responsibility split:
- TaskBinding answers "what exact thing does this request target?"
- ContinuationBinding answers "what exact working state persists for this substantial branch?"
- ARTIFACTS answers "what exact object is this and what artifact class/lineage does it have?"
- booklet STATE answers global lifecycle/promoted defaults only
- retrieval obtains exact bytes
- presentation proves the exact target reached the user

No one component owns all meanings of "current".

### I13 — strict gain test

Compared with HM-001 pass-2 plan, selected successor B:
- handles parallel branches that A can collide
- handles trivial/current-turn tasks that A would unnecessarily force into workstreams
- avoids turning every user correction into durable project mutation
- preserves all benefits of exact-object and workstream scoping
- adds no new persistent master state

Result: STRICT_GAIN.

### I14 — non-regression

Passes analytically against:

- branch isolation
- fail-closed ambiguity
- user current-turn correction
- exact-object retrieval
- no global rebuild
- ordinary conversation remaining lightweight

## Cycle 2 — HF-001 re-entry

The re-entry attacked the selected successor.

New challenge:
does a TaskBinding become another hidden authority layer?

Resolution:
No. TaskBinding is an execution-local referent binding. It cannot accept, supersede, or promote artifacts. It points to authoritative object identities and carries the grounds by which the current request selected them.

New challenge:
does durable ContinuationBinding duplicate WORKSTREAMS?

Resolution:
It should be represented through/alongside substantial Workstream state rather than a separate global registry unless implementation evidence later shows Workstream semantics are insufficient.

New challenge:
what about a fresh chat with no explicit workstream?

Resolution:
Use an unambiguous promoted/default continuation when one exists; otherwise OPEN. Do not reconstruct by search.

New challenge:
what about "these are the pages" in the present turn?

Resolution:
The TaskBinding resolves immediately. Durability/promotion is a separate material-event question.

No further upstream dependency changed the repair frontier.

## Cycle 2 terminal result

recursive_reentry: NOT REQUIRED.

Relative closure reached for the present evidence and target.

## RecommendationSet

1. CHANGE — Replace the pass-2 single "active working set" concept with a two-tier TaskBinding / ContinuationBinding model.
2. ADD — Add a typed TASK/CONTINUATION -> ARTIFACT TARGET interface contract upstream of IFACE:ARTIFACT-TO-PRODUCTION.
3. CHANGE — Extend JHB runtime bootstrap and substantial Workstream records to resolve exact task targets by predicate/scope before artifact retrieval.
4. KEEP — Preserve ARTIFACTS, exact-object preflight, accepted repair baselines, acceptance gates, and fail-closed search semantics as downstream controls.
5. ADD — Make package/display/audit consumers require a resolved binding/set ID; never reselect "current/best/latest" independently.
6. ADD — Capture only genuinely durable continuation/promotion decisions through Material Event / transition machinery; current-turn targeting alone is not acceptance.
7. INVESTIGATE LATER — Generalize the pattern portfolio-wide after a JHB pilot demonstrates a second non-JHB case or Workstream schema pressure.

## Comparative judgment

The PracticalCore successor is materially superior to the HM-001 pass-2 repair plan.

The gain is not that it is larger.

It is superior because it removes two remaining failure modes in pass 2:
- branch collision from a single durable "active working set"
- over-persistence from treating every current-turn target correction as durable continuation state

while localizing the mutation to an upstream interface and reusing existing Workstream, Material Event, artifact, and exact-object machinery.
