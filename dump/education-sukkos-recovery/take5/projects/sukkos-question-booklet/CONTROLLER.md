# Sukkos Question Booklet Controller

Status: CURRENT PROJECT-LOCAL CONTROLLER
Scope: this project only
Global authority: none

## Role

The controller preserves project identity, state, source boundaries, page jobs, and change control.

It prevents the current artifact from being silently replaced by a remembered draft, a recovered alternate route, or a newly generated candidate.

## Authority order

1. Current explicit user instruction.
2. CANONICAL_BOOKLET.md for exact artifact identity.
3. CANONICAL_RENDER_POINTER_2026-09-28.md for persistent Library file identity.
4. CURRENT_STATE.md for active lifecycle and work target.
5. Current canonical conceptual authority files in this directory.
6. Explicitly admitted decisions in DECISION_LOG.md.
7. Recovered Jewish Holiday Booklet evidence.
8. Current Take-5 tool mathematics and controller contracts.
9. External research used as comparator or project-management evidence.
10. Unresolved historical material, which remains evidence only.

Recency alone does not create authority.

## Mandatory restart binding

On restart, resume, reopen, continue, or any request that depends on "the booklet":

bind CANONICAL_BOOKLET.md first
→ verify the persistent Library canonical version
→ bind CURRENT_STATE.md
→ identify the active work target
→ ignore candidates and historical alternatives unless the active work target explicitly calls for them.

No render, page edit, recombination, or conceptual revision begins before canonical artifact identity is resolved.

## Control loop

bind canonical artifact identity
→ bind current state
→ recover the governing GOAL
→ identify the affected canonical object
→ read only the authorities needed for that object
→ run distinction and transformation analysis at the necessary geometry
→ run interaction analysis when more than one object changes
→ propose a bounded delta
→ update only the owning authority
→ run impact analysis across dependent authorities
→ verify no protected coordinate regressed
→ record the result
→ close relatively or reenter.

## Candidate isolation law

A candidate page is never canonical by implication.

Generation creates a candidate.

Discussion edits the candidate branch.

Only explicit user approval promotes it.

Until promotion:
- the old canonical page remains authoritative;
- unchanged canonical pages remain untouched;
- the candidate is stored under /Projects/Sukkos Question Booklet/Candidates/;
- candidate content cannot leak into the canonical manifest.

## Swap protocol

When the user explicitly approves a page replacement:

1. Preserve the prior canonical version unchanged.
2. Create the next immutable canonical version.
3. Copy unchanged pages forward by exact file identity.
4. Replace only the named approved page.
5. Update file hashes and persistent Library ids.
6. Update CANONICAL_BOOKLET.md, the render pointer, and CURRENT_STATE.md.
7. Record the delta.
8. Run page-level and whole-booklet non-regression checks.
9. Never mix pages from different canonical versions.

## Tool use

ASSERT recovers what is actually supported.
GOAL keeps the learner outcome and success state explicit.
PD separates distinctions that change the result.
PDAudit tests whether those distinctions survive scrutiny.
MT searches transformations, viewpoints, scope changes, representations, and failure modes.
MultiObject tests relations and higher-order interactions that isolated files cannot establish.
ImprovementCore manages progress, reentry, learned failure history, and the next admissible work package.

Tool outputs do not silently become project truth. They enter through the owning authority and decision process.

## Change routing

A request to change wording routes first to EXACT_COPY.md unless the requested wording exposes a deeper model defect.
A request to change what students learn routes to LEARNER_MODEL.md and GOAL.md before copy.
A request to change the mathematical idea routes to QUESTION_MODEL.md and IS_OUGHT_BOUNDARY.md.
A request to change the Jewish concept routes to JEWISH_OPERATION.md and SOURCE_BOUNDARY.md.
A request to change why Sukkos is present routes to SUKKOS_EMBODIMENT.md.
A request to change look and feel routes to ART_DIRECTION.md unless the visual change alters page function.
A request that affects two or more authority files triggers MultiObject interaction review.

## Anti-loss laws

No canonical fact exists only in chat.
No canonical artifact is identified only by a filename.
No candidate silently supersedes a canonical page.
No replacement file silently supersedes a prior authority.
No historical recovery outranks the current canonical render without explicit promotion.
Every material change receives a state or decision record.
Every material failure receives a lesson record close to the event.
