## Gates

G_RUNTIME: actual observable execution, not committed code.
G_ORACLE: protected-behavior checks discriminate intended failures.
G_GENERALIZATION: more than the original fixture.
G_RECONSTRUCTION: math changes explain evidence better than incumbent representation.
G_PRESERVATION: rival retains protected behavior.
G_CANONICAL: downstream surfaces reconciled.

A gate failure reopens only its dependency descendants plus any premise it falsifies.

## Why?

The old program was still too ladder-like. It made Generation 2 appear downstream of a runtime result even though much of its experimental infrastructure is independent of that result. That turns one blocked edge into an unnecessary program-wide stall.

A dependency graph preserves the real ordering constraints while allowing independent work to continue. It also makes reassessment local: evidence changes the affected frontier instead of forcing either blind continuation or total replanning.
